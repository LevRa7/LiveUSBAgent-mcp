# LiveUSBAgent-mcp 0.1.0 — the LiveUSB rescue release

The first release of the LiveUSB fork. Version numbering starts at `0.1.0` for
the independent product; the upstream base it grew from was `0.6.0`. It turns
the inherited node into the bootable Debian 13 (Trixie) rescue workstation the
fork exists for: the rescue tools return real data instead of schemas, the
destructive actions either run or say why they cannot, and a checkout can now
prove its own ISO assets before a build.

## Rescue data instead of empty schemas

- **New read-only collectors**, all wired into `rescue_info`:
  - `partitions` — `sfdisk --json`, with an `lsblk --json` fallback and a
    best-effort `blkid` map;
  - `raid_lvm` — RAID/LVM/LUKS devices from `lsblk`, plus `pvs`/`vgs`/`lvs`
    and `cryptsetup status` when those binaries exist;
  - `installed_os` — mounts candidates `ro,noload` (then `ro,norecovery`, then
    `ro`) under `/mnt/rescue/`, reads `/etc/os-release` and `/etc/fstab`, and
    always unmounts in a `finally` block; Windows volumes are probed with
    `ntfsls`, without mounting;
  - `boot_efi` — `efibootmgr -v`: current boot, order and every entry;
  - `win_artifacts` — SAM/SYSTEM/SOFTWARE presence on NTFS volumes and the
    BitLocker flag, read-only.
- Collectors never raise: an unavailable one returns `{"available": false,
  "reason": ...}` (wrong platform, missing binary, no UEFI, unreadable device).
- The `summary` and `all` views include the new sections, and the old
  “requires a Linux Live USB environment” filler is gone: a section either has
  data or states its reason.

## Actions that execute, or say why they do not

- **`umount`**, **`fsck_check`** (read-only `-n`/`--readonly` checks per
  filesystem), **`chroot_exec`** (bind mounts, `chroot`, cleanup in `finally`)
  and **`grub_repair`** now really run when `dry_run=false`.
- **`win_sam_reset`** stays honest: it returns
  `{"status": "requires_interactive", "executed": false}` with the exact
  `chntpw` command line instead of pretending to have reset a password.
- `dry_run=true` remains the default everywhere, `MESH_READ_ONLY=1` still
  refuses every action, and mountpoints stay restricted to `/mnt/rescue/*` and
  `/mnt/scratch/*`.
- **Mount I/O guard.** `mount_safe` and `mount_auto` now check
  `dmesg_io` first: more than ten active kernel I/O errors refuses the mount
  (`pass force=true to override`) instead of touching a drive that is already
  failing. Writes to volatile `tmpfs`/`overlay` destinations remain refused.

## Kiosk and zero-config onboarding

- The graphical kiosk (`127.0.0.1:8787`, `tty1`) and the console dashboard
  (`firstboot_tui.py`, `tty2`) ship with Wi-Fi scanning and hidden-SSID entry, a
  live Ethernet / USB-tethering status including the iPhone trust prompt, an SVG
  QR code and a detected-disks summary.
- The network view now has an explicit internet banner: link-up is not internet.
  With no reachability it says «Интернет не обнаружен…»; when internet appears it
  switches to a pending ready view («Интернет есть, получаем токен…») and then
  to the QR/token view once the session is registered. The QR view carries a
  short instruction to scan the code or open the connect URL and choose
  Gemini/ChatGPT/Claude.
- **«Открыть терминал»** is available on both the network and ready views. It
  calls `POST /api/terminal`, launches `xterm` running `bash` on the local X
  display and never goes through a shell or accepts a user command. The image
  ships `xterm`; `start-kiosk.sh` exports `:0`. If it reports unavailable
  (`503`), `Ctrl+Alt+F2` → `[S] Shell (bash)` is the fallback.
- **«Приложения»** opens an allowlisted launcher (`GET /api/apps`,
  `POST /api/apps/launch`): terminal, file manager (`xfe` via the
  `rhm-open-files` wrapper, `pcmanfm` fallback) and text editor (`mousepad`).
  The browser sends only an id; the argv is chosen server-side. The file
  manager opens `/mnt/rescue` (fallback `/root`) and the wrapper dismisses
  Xfe's root warning automatically.
- On boot the node registers itself with the gateway
  (`POST /v1/liveusb/register`), keeps the credential in RAM only
  (`/run/rhm-live/`, 24-hour TTL), and the `/connect/<session_code>` page hands
  out ready-made Gemini/ChatGPT/Claude endpoints. `session.json` is `0600` and
  never contains the device token.
- A gateway value may be a bare host (`https`/`wss` is implied) or an explicit
  `https://`/`wss://` URL; plaintext `http://` is refused for non-loopback
  hosts.

## ISO builder and release checks

- **`ops/live-usb/build-iso.sh --check`** validates a checkout without root and
  without `live-build`: required files, `bash -n` for every shell script and the
  chroot hook, `py_compile` for the Python runtime, the generated package list,
  the systemd unit and the GRUB menu. It prints a `PASS`/`FAIL` line per check
  and exits non-zero on the first broken checkout, before anything is written.
- The builder itself is unchanged for `--build`: three GRUB entries
  (`toram`, `Low RAM`, `Memtest86+`), automatic LVM/mdadm activation disabled,
  udev automounting disabled, a 50 MB volatile journald cap, and APFS/ZFS DKMS
  modules compiled in a chroot hook.
- `.gitattributes` pins LF for `*.sh`, `*.hook.chroot` and `*.rules`, so a
  Windows checkout cannot feed CRLF into a Debian chroot.
- CI: `.github/workflows/liveusb-iso.yml` runs the LiveUSB test modules and
  `build-iso.sh --check` on every pull request; the real ISO build is a
  manual/tag-only job in `debian:trixie` that uploads an artifact and is allowed
  to fail without blocking anything.
- `docs/liveusb/README.md` and `docs/liveusb/TROUBLESHOOTING.md` document the
  build, the write, the boot and the common failures.

## Security hardening

- The kiosk server binds to loopback only and enforces `Host`, `Origin` and CSRF
  checks on mutating endpoints; the `/connect/` page is served with a CSP nonce
  and `X-Frame-Options: DENY`.
- Outbound agent calls require TLS 1.2+ and refuse redirects.
- `load_skill` rejects `..` traversal and absolute paths outside a skill's
  `references/` directory; fetched external skills record their resolved commit
  SHA in a lockfile and are scanned offline when SkillSpector is installed.
- Everything destructive is opt-in: `dry_run` by default, read-only mounts by
  default, an explicit `writable`/`force` flag to go further.

## Local ISO build and QEMU boot (2026-11-23)

A real build was performed on Debian 13.5 (Trixie) inside WSL2 with KVM:

- `ops/live-usb/build-iso.sh --build` produced a **1.8 GB** hybrid ISO,
  `LiveUSBAgent-0.1.0-final.iso`, SHA-256
  `bb6dff194c00e1b2194aa9cad2ae4dbaea4ffe5d2e9e3092bc1884885992b79d`.
- QEMU 10.0 with OVMF/UEFI loaded the GRUB menu, then
  `/live/vmlinuz` and `/live/initrd.img`; the built image booted to
  `graphical.target`, started `rhm-live-agent.service`, and the
  `rhm-live-kiosk.service` brought up Chromium on `tty1`.
- The local build exposed and fixed five packaging defects: `dmraid` is gone
  from Trixie, `/tmp` is too small for `lb build`, the WSL Windows `PATH`
  corrupted live-build's `binary.sh`, GRUB referenced unversioned kernel
  paths that live-build did not create, and live-config's default "user"
  login kept the image at a prompt instead of the kiosk. The latter is now a
  dedicated `rhm-live-kiosk.service` that owns `tty1` and masks
  `getty@tty1`.
- The native `linux-apfs-rw` DKMS module failed to autoinstall for kernel
  `6.12.118+deb13-amd64` (`Module version 0.3.13? for apfs.ko.xz`), but the
  `apfs-fuse` binary was built and installed. ZFS and `broadcom-sta-dkms`
  autoinstalled successfully.

## Known limitations

- **No prebuilt ISO is attached to this release.** The verified artefact is
  produced locally; the ISO CI job produces an artifact only when it is run by
  hand (or on a `v*` tag).
- **Physical hardware is not validated.** The image has now booted in QEMU
  UEFI, shown the real kiosk on VNC and passed the UI click-through harness;
  a boot on a real USB stick, real UEFI/BIOS machines, real
  Wi-Fi/iPhone/Android tethering and real failing disks is still required.
  The VNC view showed the kiosk pending state because the QEMU network had no
  reachable gateway to register with.
- APFS (`apfs-dkms`), ZFS and `broadcom-sta-dkms` are unsigned out-of-tree
  modules: they do not load while Secure Boot is enabled. On this build the
  native APFS DKMS module failed; `apfs-fuse` is installed and is the
  read-only fallback. FileVault volumes are read-only.
- `win_sam_reset` is interactive by design — it plans the `chntpw` run and never
  writes to a SAM hive silently.
- A LiveUSB keeps no state across reboots: credentials, logs and session data
  live in RAM.
