# Remote Harness MCP 0.5.1 — a fresh install can start again

A patch release for 0.5.0, which could not be installed from scratch on either
platform.

## What was broken

0.5.0 moved every OS-specific behaviour into a package, `core/platforms/<os>/…`.
Both installers bootstrap a new node by *fetching a list of files*, and both lists
were flat (`core/*.py`): the package was never downloaded. A node installed that
way — `curl … | bash` on Linux, `irm … | iex` on Windows — died on the first
import:

```
ImportError: cannot import name 'platforms' from 'core'
```

A node that already had the code (`mesh_update`, `npx`, a git checkout) was not
affected, because the update payload ships the whole tree. Only a **fresh**
install was broken, which is exactly the case the curl and npx packages exist for.

## The fix

- `install.sh` and `install.ps1` fetch `core/platforms/…` with its directories,
  and create each file's parent directory before writing (a nested path used to
  fail silently).
- `install.ps1` was also missing `agent_harness.py`, `code_cache.py`,
  `device.py`, `hooks.py`, `policies.py`, `rekey.py`, `redact.py`, `schemas.py`,
  `subagents.py`, `termux.py` and `triggers.py`; its list now matches
  `install.sh`.
- `tests/test_installer_bootstrap.py` walks `core/` **recursively**, checks that
  both installers agree with the tree, and then does what the installer does:
  copies exactly the listed files into a temporary directory and imports
  `core.mcp_tools` from it. That import is what failed here, so it is now a test.

## Upgrading

Nodes on 0.5.0 update through `mesh_update` as usual — the payload is complete
there. Nothing else changed in this release.

`npx remote-harness-mcp@0.5.1` and `gemini-computer-use@0.5.1` publish the same
code; the curl installers on the shared domain were redeployed with it.
