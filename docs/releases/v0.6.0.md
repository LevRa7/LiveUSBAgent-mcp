# Remote Harness MCP 0.6.0 — device cabinet, security hardening, and a usable console menu

A feature-and-security release. It adds the first real device cabinet, closes the
findings of the 2026-11-19 audit, and replaces the console menu's repainting with
a proper terminal frame.

## Device cabinet (P1)

- **One device inventory.** `registry.json` (credentials) and `account.db`
  (owner, display name, tenant) are joined into a single list, so the cabinet
  shows every device of the signed-in owner with its platform, online state and
  last activity.
- **Pairing confirmation from the cabinet.** A pairing code can be confirmed in
  the browser (`P1-B`) instead of only through the admin API.
- **Unclaimed devices are opt-in.** A node registered before the cabinet existed
  is not shown to anybody until the owner adopts it with its link key (`P1-C`).

## Security (2026-11-19 audit)

This release closes 20 findings of the audit; the remaining ones are documented
residuals (operator trust, release signing, separate share origin).

- **Shares are sandboxed:** a user-published HTML file can no longer read the
  cabinet. Every relayed share carries `Content-Security-Policy: sandbox …`,
  `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`; a
  protocol-relative `Location` is rejected.
- **No anonymous inventory:** unknown node names answer with the same `401` as a
  wrong credential, an unknown or offline share answers `404`, `/health` is a
  bare `{"status":"healthy"}` unless the caller proves a credential (or the
  operator sets `MESH_PUBLIC_HEALTH=1`), and `/api/register` no longer suggests
  which name is taken.
- **Link keys are hashed at rest.** `link_key_sha256` replaces the plaintext
  value; existing registries are migrated on startup, and a reinstall keeps the
  old digest as an overlap until an explicit rotate.
- **Credentials stop travelling in URLs:** a device token in the query string is
  only accepted with `MESH_ALLOW_LEGACY_QUERY=1`, and rotate/revoke accept it in
  a header only. `/api/register` ignores a token supplied in the query.
- **Rate limits actually bind:** `client_ip` trusts `X-Forwarded-For` only from
  `MESH_TRUSTED_PROXIES` (last hop), the rate-window map is bounded, pairing has
  a per-address quota and evicts the oldest request instead of failing everyone.
- **Smaller fixes:** unknown `MESH_REGISTER_MODE` fails closed, usernames are
  limited to 40 characters, admin tokens are comma-separated and must be at
  least 32 characters (optional TOTP via `MESH_ADMIN_TOTP_SECRET`, optional
  `MESH_ADMIN_REQUIRE_LOCALHOST=1`), the registry read is cached per file
  identity, share relay bodies are capped and concurrency-limited, shell
  classification rejects pipelines after a "safe" prefix, and the secret
  redactor masks short and `$`-prefixed passwords.
- **Cabinet login:** the OAuth flow is bound to the browser that started it, the
  CSRF check verifies `Origin`, login is rate-limited, and an optional
  `MESH_OWNER_EMAILS` / `MESH_OWNER_DOMAINS` allowlist keeps a shared gateway to
  its owners. `MESH_CLOSE_REGISTER_WITH_ACCOUNT=1` closes self-registration when
  the cabinet is on.

## Console menu (`rhm`)

- **A frame that fits.** The menu is computed for the current window, never
  taller than it, and repainted through the Win32 console API
  (`FillConsoleOutputCharacter`/`SetConsoleCursorPosition`) so plain `conhost`
  works without ANSI or VT processing. Unchanged frames are not repainted.
- **Token and QR in the menu.** `Token: lk_…` and the MCP endpoint are always
  visible; the QR is drawn beside the status block on a wide window, below it on
  a tall one, and `e` opens it full-screen otherwise.
- **Home has an edit affordance:** `Home:  <path>  [d] edit`.
- **Keys work in any layout.** Input is read as Win32 virtual-key codes
  (`VK_D` → `d`), so pressing the physical key works with the Russian layout too;
  the `msvcrt` fallback translates Cyrillic characters to their Latin keys.
- **`rhm` no longer crashes on start** (`Keys` now implements the context-manager
  protocol) and prints once when stdout is redirected instead of repainting a
  stream.

## Changes you should know before upgrading

- **The persistent `goal` is disabled by default.** One objective stored on the
  node was shared by every chat, so the tool is absent from `tools/list`,
  `mesh_status` returns `goal: null`, and the menu hides the line. The old
  behaviour is available with `MESH_GOAL=1`; per-chat scoping is not implemented.
- **`/health` is private by default** (see above).
- **An admin token shorter than 32 characters no longer works.**
- **Unknown `MESH_REGISTER_MODE` values mean "closed".**
- **A device token in a URL needs `MESH_ALLOW_LEGACY_QUERY=1`** (migrate, rotate,
  then remove the flag).
- A reinstall rotates the link key; the previous URL keeps working until the
  owner rotates it explicitly.
